## 1. Why an amendment is needed (recap of the pre-arming evidence)

The F0 OC study established two facts about the frozen design (72 observation
units = 2 held-out models × 2 fixture crops × 18 transform conditions, analyzed
by the unit-level paired bootstrap of `paired_arm_statistics.py`):

1. **INCONCLUSIVE-dominated at n = 72 under symmetric discordance.**
   P(INCONCLUSIVE) = 1.000 at every simulated Δ_true (−0.1 … +0.5), confirmed
   at the full preregistered 10000 bootstrap resamples; P(SUCCESS) ≥ 0.8 only
   in a narrow near-nested band Δ_true ≈ 0.1–0.2.
2. **Pseudoreplication.** The 72 units are clustered (views/crops of the same
   candidate under the same held-out model); with intracluster correlation ICC
   the effective unit count is n_eff ≈ N/(1 + (m−1)·ICC), so the unit-level
   bootstrap understates the variance of Δ̂ and the F0 decision probabilities
   are *optimistic*.

The v2 cluster-aware OC study (this proposal's evidence base) regenerates the
grid under clustered DGPs at the REAL protocol geometry: each cluster is one
base image contributing m = 36 members (18 transformation views × 2 fixture
crops), and the dependence axis is the **realized ICC** (labeled grid values
{0.0, 0.25, 0.5} are verified against the measured per-cell mean ANOVA
estimate, reported as `mean_estimated_icc` in the artifact — agreement within
±0.02 at every cell). It runs BOTH the frozen-equivalent unit-level analysis
and the proposed cluster-robust analysis
(`ruthless_pipeline/certification/cluster_paired_arm_statistics.py`) on the
SAME synthetic datasets. It confirms both F0 findings directly: under ICC > 0
the unit-level path's intervals are far too narrow and its coverage of the
true Δ collapses (e.g. 0.44–0.49 at ICC = 0.25), while the cluster-robust
path's coverage stays in 0.85–0.985 (see §3 for the honest coverage
statement — nominal 0.95 is NOT claimed).

The design correction is therefore two-fold and inseparable: **(i) redefine
the inferential unit as the cluster (the base image)** and **(ii) size the
design in clusters, not views**.

## 2. Proposed design correction

### (a) Inferential-unit definition — clusters, not views

The inferential unit of the primary comparison is redefined as the
**independent base image**: all transformation views and crops of one base
image — under BOTH arms — are members of that image's cluster and are
**explicitly declared pseudoreplicates** (correlated re-observations of the
same underlying randomness), never independent units. Concretely (v2 — the
v1 "base-image × held-out-model block" definition is replaced, per red-team
F3, because both arms score the same images and image×model clusters sharing
an image would be cross-correlated):

- one cluster = one **base fixture image**; its members are the 36
  (view × crop) paired observations — 18 transformation views × 2 fixture
  crops — each member contributing the paired outcome (arm M detected?, arm C
  detected?) on the SAME rendered view;
- the primary endpoint remains the paired per-member outcome and
  Δ = R_M − R_C pooled over members, so the estimand is unchanged;
- inference (the bootstrap interval for Δ) resamples **clusters** (images)
  with replacement, carrying all members of a resampled cluster, via
  `cluster_paired_arm_statistics.cluster_paired_arm_statistics` with the
  preregistered z, seed, resample count, and decision regions; per-arm Wilson
  intervals are still reported for descriptive comparability;
- a fail-closed guard (`min_clusters`, preregistered default
  `DEFAULT_MIN_CLUSTERS = 8`) aborts the primary comparison rather than
  emitting a cluster bootstrap over too few clusters;
- the module reports the intracluster-correlation / design-effect diagnostic
  (ρ̂, n_eff) alongside every result so the pseudoreplication level of the
  realized data is disclosed, not assumed; at zero total variance the
  diagnostic is reported as **NA (null)**, never as the misleading
  ρ̂ = 0 / n_eff = N (red-team F7 fix);
- **documented divergence from the frozen path (red-team F8 fix):** the
  cluster module corrects the percentile-bootstrap lower-index off-by-one
  that the frozen unit-level path carries (frozen: `floor((α/2)·R)`, i.e. the
  26th order statistic at R = 1000; corrected: the 25th). The frozen module
  `paired_arm_statistics.py` is NOT modified. The correction moves only the
  lower bound, at most one order statistic downward; on singleton clusters
  the two modules otherwise agree bit-for-bit, and the divergence is pinned
  by `tests/test_cluster_paired_arm_statistics.py`.

### (b) Multi-image fixture protocol (NEW in v2 — red-team F3)

The v1 draft never confronted the fact that the current pinned fixture (ONE
base image `source-zidane.jpg`, 2 crops) has **K = 1–2 clusters** under any
cluster definition — far below `min_clusters = 8`, so the proposed analysis
would fail closed on today's data. The amendment is therefore not merely an
analysis change: it **requires a new multi-image fixture protocol**, specified
here as a frozen protocol input:

- **K ≥ 72 independent base images** (see §2(c) for the derivation and the
  ICC sensitivity), sourced independently of the candidate pipeline, each
  content-pinned by SHA-256 in the fixture manifest exactly as
  `source-zidane.jpg` is pinned today;
- per image: the existing frozen 18-transformation sweep × the existing 2
  fixed crop specs of `run_measured_benchmark.prepare_fixture` = **36 members
  per image**, each member scored under Arm M and Arm C on the same rendered
  view (the pairing is within-member);
- total design size: K × 36 paired member observations (K = 72 → 2592
  members per arm); the analysis clusters **images**, not arms and not
  views;
- image sourcing, crop specs, and the hash manifest are frozen BEFORE arming
  as part of executing A5; no image may be selected or rejected on the basis
  of any measured outcome.

**Stated limitation (unmodeled dependence):** the v2 DGP draws clusters
independently with a single common ICC. Real view-level heterogeneity (some
transforms more correlated than others) and any residual cross-image
correlation induced by shared pipeline components are NOT modeled. The
realized ICC must be **measured during rehearsal** via the reported ρ̂
diagnostic on outcome-free rehearsal data; if the realized ICC materially
exceeds 0.25, the cluster count must be raised per the sensitivity table in
§2(c) BEFORE arming, via the same pre-arming amendment mechanism.

### (c) Sample size — minimum cluster count (v2, corrected axis and geometry)

contributing its full 36-member grid, replacing the current "72 observation
units" framing and superseding the v1 "K = 108 × 6 members" figure (which was
keyed to the miscalibrated axis and a geometry with no protocol referent).

full table in §3 and in

The proposed K is the **smallest simulated cluster count at which the
cluster-robust analysis achieves P(SUCCESS) ≥ 0.8 for Δ_true = +0.2** under
**ICC = 0.25** symmetric discordance. **Provenance disclosure (red-team F6):**
this K is a grid pick from K ∈ {8, 12, 18, 24, 36, 72} — the grid brackets
0.130 (K = 36) and 0.995 (K = 72), so the true minimum lies between them and
72 is the smallest *simulated* value meeting the rule; the answer is
conditioned on the ICC assumption, which is why the realized-ICC measurement
requirement of §2(b) exists. Justification for keying to ICC = 0.25: views of
one base image share its content but differ by construction under the
transform sweep, so a moderate ICC is the plausible regime; ICC = 0.25 is
also the level at which the v1 grid's mid cell actually sat (its "ρ = 0.5"
label meant realized ICC ≈ 0.25).

**ICC sensitivity (honest):** at ICC = 0 the requirement collapses to K ≥ 8
(P(SUCCESS) = 0.915 at K = 8 — though coverage there is only 0.850, see §3);
at ICC = 0.25 the requirement is K = 72; at ICC = 0.5 even K = 72 delivers
only P(SUCCESS) = 0.070 (design-effect extrapolation, disclosed AS
extrapolation since it lies off the simulated grid: deff = 1 + 35·ICC, so
matching the n_eff ≈ 266 of the K = 72 / ICC = 0.25 cell at ICC = 0.5
requires K ≈ 137, i.e. **K ≈ 144**). The design is therefore keyed to a
verified ICC ≤ 0.25; the rehearsal measurement of §2(b) is a hard gate.

Note what this proposal does NOT do: it does not widen the width gate, move
α, or redraw decision regions. It buys power the only legitimate way — more
independent replication — and it makes the inference honest about clustering.

### (d) More views per image does NOT substitute for more images

The members-per-cluster sweep (fixed Δ_true = +0.2, ICC = 0.25, K = 18
clusters; m ∈ {2, 6, 18, 36} members per cluster) shows that once K is below
the cluster-count requirement, no feasible within-image replication rescues
the design:

| m members/cluster | CLUSTER P(SUCCESS) | CLUSTER CI width | CLUSTER coverage |
|---|---|---|---|
| 2 | 0.000 | 0.477 | 0.950 |
| 6 | 0.005 | 0.376 | 0.940 |
| 18 | 0.010 | 0.322 | 0.895 |
| 36 | 0.000 | 0.318 | 0.955 |

At K = 18, P(SUCCESS) is ≈ 0 at every m — the width gate is never met because
cluster-level variance (governed by K) dominates: an 18× increase in
within-cluster replication buys nothing, while increasing K from 18 to 72 at
fixed m moves P(SUCCESS) from 0.000 to 0.995. **Correction to the v1 text
(red-team F2):** v1's headline "members do not substitute for clusters" was
stated too strongly — within-cluster replication DOES help up to the
saturation point (removing the (1−ICC)/m share of member-level noise), and
the protocol's real geometry (m = 36) already sits at that saturation point.
The correct statement is: **past m ≈ 18–36, only more clusters help**, and
the binding constraint at the real geometry is the cluster count K.

### False-success control

At Δ_true = 0 and Δ_true = −0.1 the cluster-robust path never returns
SUCCESS at Δ_true = −0.1 (P(SUCCESS) = 0.000 at every simulated cell) and at
Δ_true = 0 its false-success rate at the recommended K = 72 is 0.030–0.035
across ICC — near the nominal one-sided 2.5%. Honest disclosure (red-team
F4): at very small K the rate is elevated — 0.085 at (Δ = 0, ICC = 0, K = 8),
about 2.5 Monte Carlo SE above nominal — a known small-sample
anti-conservatism of the percentile cluster bootstrap; it is NOT within
Monte Carlo error of nominal and we do not claim otherwise. It is mitigated
by design sizing (at K ≥ 18 the maximum observed false-success is 0.035), not
by assertion. The frozen unit-level path remains invalid under clustering: at
Δ_true = 0 it manufactures false SUCCESS at high rates (e.g. its spurious
P(SUCCESS) at Δ = +0.2, ICC = 0.25 reaches 0.815–1.000 with coverage ≈ 0.44
— the same variance understatement that inflates power also manufactures
false positives at Δ = 0).

### Coverage — stated honestly (red-team F4)

**Nominal 95% coverage is NOT claimed.** Across the Δ_true = +0.2 grid the
cluster-robust path's achieved coverage is 0.850–0.965: systematically
1.5–3 Monte Carlo SE below 0.95 at small K (0.850 at K = 8, ICC = 0; 0.865–
0.895 at K = 8–12 under ICC > 0) and 0.895–0.965 at K ≥ 18, with no monotone
trend in K — a mild, systematic anti-conservatism of the percentile cluster
bootstrap, also present in the frozen unit-level path's construction. At the
recommended K = 72, achieved coverage is 0.925–0.955 across the simulated ICC
range. **The calibrated claim is therefore: two-sided coverage ≈ 0.90–0.95 at
the recommended design point, not 0.95.** Fixing this properly (BCa or
bootstrap-t cluster intervals) is a candidate future pre-arming amendment; it
is NOT smuggled into this one. What matters for the decision regions is that
(a) false-success at Δ ≤ 0 stays near nominal at the recommended K, and (b)
the invalid unit-level alternative is catastrophically worse (coverage
0.32–0.49 under ICC ≥ 0.25), so the cluster path remains the only defensible
option even with its mild undercoverage disclosed.

### Distinguishability floor — stated honestly (red-team F5)

The design is confirmatory only for effects Δ ≥ 0.2 and only at verified
ICC ≤ 0.25:

- at (Δ_true = +0.1, ICC = 0.25, K = 72): P(SUCCESS) = 0.700;
- at (Δ_true = +0.1, ICC = 0.5): P(SUCCESS) ≤ 0.015 at every simulated K;
- at (Δ_true = +0.2, ICC = 0.5, K = 72): P(SUCCESS) = 0.070.

Given that the program's only attested held-out measurement regime (D2-0004,
closed) sat at boundary rates with Δ ≈ 0, the memo states plainly: **this
design cannot detect small-to-moderate effects (Δ ≈ 0.1) at realistic ICC**;
it distinguishes the Δ ≥ 0.2 hypothesis from Δ ≤ 0 with controlled error, and
nothing more. A SUCCESS result supports "Δ > 0"; an INCONCLUSIVE at small
true Δ is an expected design limitation, not an anomaly.

## 4. Decision memo — recommendation among the pre-registered options

The F0 study's option set for D2-0005, evaluated strictly on the pre-arming
OC evidence above (no outcome data exists; no threshold is moved):

1. **Retain D2-0005 as a pilot-sized / exploratory prospective experiment
   (PILOT).** Viable and honest, but spends the entire experimental budget to
   produce an INCONCLUSIVE-dominated or exploratory-only result; it does not
   deliver the confirmatory decision the program needs at Δ_true = +0.2. Keep
   only as the disclosed fallback if the fixture requirement below is
   operationally infeasible.
2. **Increase genuinely independent units (clusters), holding the frozen
   unit-level analysis (MORE_INDEPENDENT_UNITS alone).** Rejected as
   insufficient on its own: under intracluster correlation the unit-level
   path is not merely low-powered, it is *invalid* — coverage falls to
   0.32–0.49 at ICC ≥ 0.25 and its apparent power (P(SUCCESS) up to 1.000 at
   Δ = +0.2) is spurious precision from counting pseudoreplicates as units.
   Adding units to an invalid analysis manufactures confident wrong answers.
3. **Revise the inferential method (cluster-robust bootstrap), holding the
   frozen single-image fixture (REVISE_METHOD alone).** Rejected as
